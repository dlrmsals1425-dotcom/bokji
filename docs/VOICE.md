# 말로 찾기 음성 입력

`/situation`의 자유문장 입력칸에 한국어 음성 입력을 추가한다. 음성을 글로 바꾼 다음 사용자가 확인·수정하고 **입력칸에 넣기**를 눌러야 기존 글 뒤에 추가된다. 문장 해석과 혜택 찾기는 기존 버튼으로 직접 실행한다.

## 사용 방법

1. 말로 찾기 화면에서 음성 처리 안내를 읽고 동의한다.
2. **음성 입력 시작**을 누른다. 브라우저에서 마이크 권한을 요청하면 직접 허용한다.
3. 사는 곳과 상황을 이어서 말하고, 다 말했으면 **말하기 완료**를 누른다.
4. 인식 문장을 확인·수정한 뒤 **입력칸에 넣기**를 누른다.
5. **이 문장으로 아래 칸 채우기**를 눌러 기존 해석 결과를 확인한다.

기존 글은 보존하며 공백을 구분자로 이어 붙인다. 음성과 기존 글을 합쳐 500자(자바스크립트 문자열 길이)를 넘으면 자르지 않고 수정 안내를 보여 준다. 빈 인식 결과를 답변이나 건너뛰기로 처리하지 않는다.

## 브라우저와 개인정보

- `SpeechRecognition` 또는 `webkitSpeechRecognition` 생성자를 지원하는 브라우저에서만 음성 컨트롤을 표시한다. 생성자 존재가 실제 인식 성공을 보장하지는 않는다.
- 언어는 `ko-KR`, `continuous=true`로 여러 문장의 최종 결과를 모은다. 첫 문장 결과에서 마이크를 끊지 않는다. **말하기 완료** 또는 시작·권한 대기 시간을 포함한 20초 제한에서 중지하고, 마지막 결과를 최대 2초 더 기다린다. 브라우저 자체가 인식을 먼저 종료하면 그때까지의 문장을 확인창에 보여 준다.
- 결과는 브라우저가 준 인덱스별로 보관해 누적 이벤트의 같은 문장이 중복되지 않게 한다. [Web Speech API의 continuous 규약](https://webaudio.github.io/web-speech-api/#dom-speechrecognition-continuous)을 따른다.
- 브라우저 제공업체의 서버로 음성이 전송될 수 있다. 브라우저·운영체제·권한·네트워크에 따라 동작이 다르며 모든 환경과 오프라인 동작을 보장하지 않는다.
- 앱에 별도 녹음 저장, STT 서버, 유료 SDK, API 키, 전사문 로그를 추가하지 않았다. 원문은 화면 상태에만 두며, 사용자가 기존 해석·혜택 찾기를 실행한 뒤의 구조화된 답변은 기존 기기 내 저장 정책을 따른다.
- 취소, 동의 철회, 직접 타이핑, 찾기 대상 변경, 문장 해석, 화면 이동, 탭 숨김 때 진행 중 인식과 확인 대기 문장을 폐기한다. 이전 세션의 늦은 콜백은 무시한다.
- 미지원, 권한 거절, 무음, 연결 오류에서는 안내를 표시하고 직접 입력을 유지한다.

## 로컬 실행

작업 브랜치는 `jinwoo`다. Windows PowerShell에서는 이 저장소 디렉터리에서 다음을 실행한다. 다른 UI 작업 서버와 구분하기 위해 포트 3220을 쓴다.

```powershell
npm.cmd ci
npm.cmd run build
npm.cmd run start -- -p 3220 -H 127.0.0.1
```

음성 화면: <http://127.0.0.1:3220/situation>

macOS/Linux에서는 `npm.cmd` 대신 `npm`을 사용한다. 기존 package/config 및 의존성은 이 기능을 위해 변경하지 않았다.

## 검증

2026-10-16(Asia/Seoul), 이 음성 브랜치에서 직접 실행한 결과:

| 검사 | 결과 |
|---|---|
| `npm.cmd run lint` | 통과, 오류·경고 없음 |
| `npm.cmd run typecheck` | 통과 |
| 음성 browser/text + 기존 parse 단위 검사 | 91/91 통과 (29 + 27 + 35) |
| `npm.cmd run build` | 프로덕션 빌드 통과 |
| 음성 Playwright E2E | 20/20 통과 (데스크톱 16, 모바일 4) |
| 인앱 브라우저 화면 확인 | 데스크톱·390×844 모바일 폭에서 음성 패널 확인, 확인 중 console 오류·경고 없음 |

재현 명령(빌드한 앱을 3220에 먼저 실행):

```powershell
npm.cmd run lint
npm.cmd run typecheck
npm.cmd test -- tests/unit/voice-browser.test.ts tests/unit/voice-text.test.ts tests/unit/parse.test.ts --maxWorkers=1
$env:E2E_BASE_URL='http://127.0.0.1:3220'
npm.cmd run e2e -- tests/e2e/voice.spec.ts --workers=1
```

Playwright Chromium이 없으면 `npx.cmd playwright install chromium`을 먼저 실행한다. Windows 샌드박스에서는 Next/Vitest의 경로 확인이 `Access denied`/`EPERM`으로 막혔으며, 허용된 실행 환경에서 동일 명령으로 검증했다. 앱 코드를 바꾸어 우회하지 않았다.

E2E는 앱 로드 전에 가짜 SpeechRecognition을 설치한다. 첫 문장 뒤 계속 듣기·여러 문장 합치기, 동의·확인 전 입력 불변, 전사문 수정, 한 번만 추가, 자동 해석·제출 없음, 미지원·거절·무음, 취소·철회·문맥 변경 뒤 늦은 응답, 재녹음, 500자 초과를 검사한다. 탭 숨김은 가짜 visibility 이벤트로 검사했다. 실제 마이크나 외부 음성 서비스는 호출하지 않았다.

초기 단일 문장 구현의 mock 검사는 통과했지만 사용자가 실제 사용 중 너무 빨리 끊긴다고 보고했다. `continuous=false`와 첫 final 결과에서 즉시 종료하던 처리를 수정하고 위 검사를 다시 실행했다. mock 통과가 실제 발화 경험을 보장하지 않음을 이 이력과 함께 남긴다.

**미검증:** 실제 한국어 발화 인식률, 실제 마이크 권한 창, 실제 기기의 백그라운드 전환, Chrome/Safari 등 브라우저별 음성 서비스. 모바일 E2E는 Chromium 기기 에뮬레이션이며 실제 휴대폰 검사가 아니다. 전체 앱 E2E와 전체 단위 검사를 이번 음성 검증 결과로 주장하지 않는다.

실사용 확인 시 짧은 가상 문장으로 권한 허용·거절, 인식 문장 수정·추가, 탭 전환과 재시도를 점검한다. 실제 개인정보로 시험할 필요는 없다.

## 코드 범위

- `src/components/VoiceInput.tsx`, `VoiceInput.module.css`: 동의·시작·확인·취소 패널.
- `src/lib/voice/browser.ts`, `types.ts`: 브라우저 인식과 단일 세션 수명 관리.
- `src/lib/voice/text.ts`: 기존 글 보존과 합산 길이 검사.
- `src/app/situation/SituationForm.tsx`: 입력 패널 연결과 문맥 변경 시 취소.
- 홈·소개·푸터·메타데이터: 브라우저 음성 전송 가능성에 맞춘 개인정보 안내 수정.

질문 흐름, 추천 알고리즘, `/ask`, 데이터와 기존 화면 디자인은 변경하지 않는다. 배포·main 병합은 이 작업에 포함되지 않는다.
