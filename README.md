# 복지나침반 (MVP)

로그인 없이 12개 간단한 질문으로 **중앙정부·청 / 시도 / 시군구 / 공공기관** 복지 서비스를 찾아
**조건 충족 · 가능성 있음 · 확인 필요** 3단계로, 이유와 함께 보여주는 서비스입니다.
입력값은 서버로 보내지 않고 브라우저 안에서 판정합니다. (기획: `/workspace/welfare-plan/기획안.md`, `설계서.md` v0.3)


## 화면 흐름 (로그인 없음)

1. **홈** `/` — 시작 버튼, **예시 상황 4개(원클릭, `예시` 표시)**, 키워드 검색, 3단계 설명, 데이터 규모. 로그인은 비활성 `🔒 로그인 준비 중` 버튼만.
   예시 링크: `/results?example=suwon-senior | seongnam-single-parent | goyang-youth | bucheon-disability`.
2. **입력** `/check` — 5단계 12개 항목(거주지만 필수, 나머지는 모두 `모름/건너뛰기`). 장애·돌봄은 선택 입력.
   이 기기(localStorage)에만 저장, `공용 기기 모드`(sessionStorage), `이 기기에서 지우기`.
3. **결과** `/results` — **먼저 확인해 보세요(관련도 상위 5개)** + 3단계 탭 + 기관 유형·분야 필터 + 결과 내 검색.
   **관련도 정렬**(내 상황을 특정하는 조건 일치 → 검수 규칙 → 지역 특정성 → 이름·대상 문구와 내 상황의 일치/불일치 → 핵심 복지 100선)
   후 탭마다 상위 10개, `더 보기`로 20개씩. 같은 이름의 시도·시군구·구 변형은 **한 카드로 묶고** `다른 기관 사업 N개 더 보기`.
   탭·분야·기관 개수 = 화면 카드(묶음) 수 — 필터를 바꿔도 목록 길이와 항상 일치.
   **기본 숨김**: 교육청, 복지 외 분야(농림축산어업 생산 지원·사업자/창업/소상공인 대상) — 필터 체크박스로 보기.
   **자동으로 받는 혜택**: 신청 유형이 `자동 제공`·`기관 추천·선정`인 사업은 추천 5개·탭 목록·개수에서 빼고, 목록 아래(`#result-list` 밖)
   접힌 영역 `자동으로 받는 혜택 (따로 신청하지 않아도 되는 경우가 많아요) N개`에 모음(조건 불일치·기본 숨김·관련도 0 이하 제외, 분야·기관·검색 필터는 동일 적용).
   카드·상세에 `✍ 직접 신청` / `🔄 자동 제공` / `🏢 기관 추천·선정` 태그(신청 방법 확인은 태그 없음), 상세 신청·문의에 판단 근거 구절.
   카드마다 판단 이유(✓ 맞는 조건 · ? 확인할 조건 · ✕ 맞지 않는 조건), `조건이 맞지 않는 서비스 N개도 보기`, 인쇄·PDF, 공유(요약만, 입력값 미포함),
   `🔒 정밀 매칭/저장·알림 (준비 중)`.
4. **상세** `/p/[id]` — 판정 근거(✓/✕/?/참고), 규칙 검수 상태와 근거 구절, 서비스 내용, 우리 지역 운영 정보(통합돌봄),
   소관/집행기관, 신청처·연락처 또는 **주민센터·시군구청·☎129/110 대체 안내**, 공식 원문 링크(없으면 복지로 검색 안내),
   출처별 **원문 기준일·수집일**, 신뢰도. `🔒 신청 준비/알림 (준비 중)`.
5. **검색** `/search`, **데이터·판정 기준** `/about`. 헤더의 `가+ 큰 글씨`는 125% 확대(설정은 기기에 저장).

※ 번들 경로로 **시군구 단위 지역**은 정적 파일 요청에 드러납니다(설계상 허용, 아래 결정 사항 참고).

### 판정 정책 (설계서 6.1·6.2)
- 규칙은 조건 트리(all/any) + 3값 논리. `모름`은 U(미확정), 묻지 않는 조건(재산·질병 등)은 항상 U.
- **검수 규칙**(verified / curated): 모두 T → `조건 충족`, U 남음 → `가능성 있음`.
- **자동 변환 규칙**(auto): 충족 조건이 있으면 최대 `가능성 있음`, 없으면 `확인 필요`.
- 비정형 핵심 조건(‘필요하다고 인정되는 자’ 등) 또는 규칙 없음 → `확인 필요`. 하나라도 F → `조건 불일치`(기본 숨김).
- 정렬: 검수 규칙 → 충족 조건 수 → 시군구·시도·전국 순.

### 규칙 검수 흐름
1. `npm run pipeline` → `pipeline/out/review-queue-gyeonggi.csv`(경기 자동 규칙), `review-curated.csv`(큐레이션 규칙).
2. 검수자가 원문과 대조 후 `pipeline/rules/review-ledger.csv` 에 `rule_id 또는 curated:<키>, verified|rejected, 검수자, 일자, 메모` 기록.
3. 재빌드하면 verified 는 `검수 규칙`(조건 충족 판정 가능), rejected 는 규칙 제거(확인 필요).
현재 큐레이션 규칙 73개는 **원문 근거 구절과 대조해 AI가 1차 작성**한 것으로, UI에 `검수 규칙(1차)`와 “최종 사람 검수 진행 중”을 표시합니다.

### 규칙 출처 표시 (UI 배지)
| 배지 | 의미 | 최대 판정 |
|---|---|---|
| `✔ 검수 규칙(1차)` | 원문 근거 구절과 대조해 작성(AI 보조), 최종 사람 검수 대기 — 데모에서 조건 충족 허용(운영자 위임 결정) | 조건 충족 |
| `⚙ API 지원조건` | 공공서비스 API `supportConditions` 코드(나이·중위소득 구간·대상 특성·가구 유형) — **전국 사업·경기도 사업만** | 조건 충족 |
| (배지 없음) | 시범 지역 밖의 API 지원조건, 복지로 태그·문구 자동 변환 | 가능성 있음 |

API 지원조건의 과대 판정 방지: 사실상 제한 없는 연령(0~120세, 19세 이상)은 조건에서 제외, 상한 18세 이하 연령은 본인 또는 자녀 나이로 판단,
지원대상·선정기준 문구에 코드에 없는 수급·장애·한부모 등 요건이 보이면 soft 조건(불충족이어도 숨기지 않고 '가능성 있음')을,
간편 입력으로 확인할 수 없는 신분 요건(피해자·가입자·농업인·근로자 등)이 보이면 '원문 요건 확인' 조건을 덧붙임.
복지로 '노년' 태그는 만 65세 이상으로 해석.

### 데이터 정리 규칙 (2026-10-02 polish)
- **지역 집행분 vs 지역 추가사업**: 정부24·복지로 시군구 등록분을 전국 사업의 '우리 지역 운영 정보'로 흡수하려면
  이름 정규화 일치 + 근거 법령 겹침 + 이름·설명에 추가사업 표지(추가·자체·특화·확대·소득무관·시비/구비·○○형 등) 없음 + 설명 유사도(글자 2-gram, 기능어 제외) ≥ 0.06 을 모두 만족해야 함.
  하나라도 어긋나면 별도 지역 사업으로 유지 (예: 수원 `장애인 활동지원(추가)`). 판단 내역: `pipeline/out/regional-copies.csv`.
- 통합돌봄 메뉴판 '미분류' 행도 이름이 전국 사업과 같고 추가사업 표지가 없으면 지역 운영 정보로 흡수(예: 시흥 `장애인활동지원`).
- **복지 외 분야 분류** (`pipeline/src/normalize/sector.ts`): 정부24 서비스분야 `농림축산어업`·농가/축산/영농 이름 → agri,
  소상공인·창업·기업·사업자 대상 → business. 농어업인 개인 복지(안전보험·건강검진·복지바우처·농지연금)와 근로자·취업·주거 지원은 제외.
  2026-10-02 보정: 생산·사업 지원(농기계·비료·상토·방제·시설/경영/창업/정책자금·판로·박람회 참가·HACCP·고용장려금 등)은 숨기고,
  사람에게 가는 복지(농어민 공익수당·여성농업인 바우처·안전재해보험·건강검진·진료비·귀농인 주택수리비, `대전형 1인 자영업자 유급병가`,
  소상공인 노란우산공제 장려금·아이돌봄 등)는 표시. 이전 대비 변경 목록: `pipeline/out/sector-changes.txt`.
- **신청 유형 분류** (`pipeline/src/normalize/applyType.ts`, 운영자 방향 2026-10-02: *내가 직접 신청해야 받는데 놓치기 쉬운 혜택*에 집중):
  `self`(본인·가족이 직접 신청) / `auto`(자동 지급·연계, 직권 신청, 학교·어린이집이 일괄 처리) / `institution`(기관·학교장 추천·의뢰, 시설·기관 대상, 운영 법인 지원) / `unknown`(정보 없음·애매 — 목록에 그대로).
  근거 순서: 전국 핵심 급여(생계급여·기초연금·아동수당·한부모 아동양육비·장애인연금·장기요양 등)는 항상 self →
  주민안전보험·단체보험 자동가입(저소득층 아동보험 등, 청구 안내가 있을 때)은 self(가입은 자동이지만 보험금은 직접 청구) → 정부24 신청방법·복지로 상세 신청방법 원문(‘별도 신청 없이’·‘개인 신청절차 없음’·‘자동 지급’·‘직권’·‘일괄’·‘명단 통보’·‘학교장 추천’·‘의뢰’) →
  정부24 신청방법 구분 `신청불필요` → 복지로 `직접 지원(별도 신청사항 없음)`(이 표기만으로는 unknown, 명절위문·건강보험료 등 이름 단서가 있을 때만 auto) → 시설·기관 대상 이름/대상/제공유형 `시설입소` → 설명 문구.
  자동 문구와 신청 안내(‘신청하시면’·‘방문 신청’·‘온라인 신청’)가 함께 있거나, 따로 신청은 없지만 직접 가서 이용해야 하는 것(예방접종·요금 감면·지역화폐)은 unknown.
  정부24의 공통 문구 ‘해당 서비스는 신청없이 자격대상자에게 자동적으로 제공됩니다’는 ‘신청 불필요’로만 보고 자동 지급 근거로 쓰지 않음.

## 환경 변수

| 이름 | 용도 | 필요 시점 |
|---|---|---|
| `DATA_GO_KR_SERVICE_KEY` | 공공데이터포털 일반 인증키 (정부24는 `Authorization: Infuser` 헤더, 복지로는 `serviceKey` 쿼리. 출력·로그·커밋 금지) | 파이프라인 수집 시만 |
| `GOV24_DAILY_BUDGET` | 공공서비스 API 일일 호출 예산 (기본 2000, 한도 10,000) | 선택 |
| `BOKJIRO_CENTRAL_BUDGET` / `BOKJIRO_LOCAL_BUDGET` | 복지로 중앙·지자체 API 일일 예산 (기본 95 / 950, 개발계정 한도 100 / 1,000) | 선택 |
| `E2E_BASE_URL` / `E2E_PORT` | e2e 대상 서버 | 선택 |

앱 런타임에는 환경 변수가 필요 없습니다. `.env.example` 참고.

## 배포 (Vercel, 아직 배포하지 않음)
- 프레임워크 기본값(Next.js) 그대로. 번들(약 20MB, 시군구 번들 gzip 평균 ~12KB)은 `public/` 정적 자산으로 함께 배포.
- 데이터 갱신 = `npm run pipeline` 후 커밋 → 재배포.

> **보안 주의:** Turbopack 로컬 캐시(`.next/cache`)는 빌드 프로세스의 환경변수를 스냅샷합니다. 셸에 `DATA_GO_KR_SERVICE_KEY` 등 비밀값이 있으면 `npm run build:safe` / `npm run start:safe`(최소 환경으로 실행)를 사용하세요. 앱 런타임은 API 키가 필요 없습니다(번들은 정적 JSON).
